# paint-by-numbers

Програма автоматичного створення картин за номерами з фотографій (див. ТЗ версії 2.0).
Без ШІ: лише класичні детерміновані алгоритми, працює без інтернету.

**Статус: етапи 1--4 (консольний запуск).** Є повний цифровий виробничий пакет: SVG і PDF у фізичних
розмірах, кольоровий еталон, специфікація фарб із розрахунком ємностей, звіт якості.
Є зони пріоритету (розділ 7.8 ТЗ). Ще немає: каталог реальних фарб (етап 5), графічний інтерфейс (етап 6).

## Запуск

```bash
uv sync
uv run python main.py photo.jpg -o out --order 000123 --name "Портрет" --mode balanced --colors 24 --width-mm 300
```

Основні параметри: `--mode simple|balanced|detailed`, `--colors 4..64`, `--width-mm`, `--height-mm`
(якщо не задано, береться за пропорціями фото; при невідповідності фото кадрується по центру),
`--px-per-mm` (робоча роздільна здатність), `--seed` (відтворюваність), `--order`, `--name`.

Специфікація ємностей (розділ 11 ТЗ): `n = max(1, ceil(S * K / N))`, де S --- площа кольору на полотні,
N --- норма покриття однієї ємності 3 мл (`--coverage-mm2`), K --- коефіцієнт запасу (`--safety-factor`, >= 1).
**N не має вбудованого значення:** її потрібно виміряти фізичним тестом. Поки N не задано й не підтверджено
(`--coverage-confirmed`), на кожен колір припадає одна ємність, а розрахунок позначений як орієнтовний.

## Зони пріоритету

Без ШІ програма не розпізнає обличчя, тому оператор сам позначає важливі місця (обличчя, очі, рот, предмет).
У зонах зберігається більше деталей: більше кольорів палітри, слабше згладжування, не прибираються тонкі
виступи, слабше спрощуються контури. Нижчий поріг площі обмежений розміром, де ще поміщається номер.

```bash
# 1) перевірити, куди потрапили зони (швидко, без генерації) -> out/zones_preview.png
uv run python main.py photo.jpg --zones examples/zones_portrait.json --preview-zones -o out
# 2) згенерувати пакет із зонами
uv run python main.py photo.jpg --zones examples/zones_portrait.json -o out
```

Формат JSON (координати 0..1, початок у лівому верхньому куті): `rect` (x0, y0, x1, y1), `ellipse` (cx, cy, rx, ry,
angle), `polygon` (points); `weight` 0..5 (типово 2; очі та рот зазвичай 3--3.5); `frame`: `canvas` (типово,
відносно полотна після кадрування) або `photo` (відносно вихідного фото). Приклади в `examples/`.
У `quality_report.json` для кожної зони є кількість ділянок, ΔE76 і SSIM усередині зони та поза зонами.
Дрібні деталі зони, куди не вміщається номер, зберігаються навмисно й потрапляють у попередження
`ZONE_NUM_NO_ROOM`: їх потрібно перевірити вручну.

`--force` формує виробничі файли попри критичні помилки (використовувати лише після ручної перевірки).

## Результат: `out/order_XXXXXX/`

```
source/original_photo.*              копія вихідного фото (оригінал не змінюється)
project/project.json                 налаштування, версії, seed, палітра, SHA-256 фото, список експортів
project/regions.npz                  розбиття на ділянки (відтворення без повторної генерації)
preview/color_preview.png            кольоровий еталон
preview/contour_preview.png          контури з номерами
preview/numbered_preview.png         контури з номерами на світлій кольоровій заливці
print/canvas_outline.svg             векторний макет у мм (кожна спільна межа один раз)
print/canvas_outline.pdf             PDF точно за розміром полотна, шрифт вбудований
palette/palette.png, paint_list.csv  палітра; перелік фарб (роздільник ';', UTF-8 з BOM для Excel)
production/production_specification.pdf|json   специфікація: номери, зразки, площі, ємності
quality/quality_report.json          метрики та попередження (код, серйозність, ділянки, рекомендація)
quality/compare.png                  оригінал | еталон | контури
```

Пакет збирається у тимчасовій папці й підміняє попередній лише після успіху. Критичні помилки
(наприклад, не пройдена перевірка топології) блокують `print/` і `production/`.
Для кирилиці в специфікації потрібен TTF-шрифт (DejaVu Sans, Liberation Sans або Arial; можна вказати
змінною `PBN_FONT`); без нього специфікація друкується англійською.

## Конвеєр

завантаження (EXIF) → згладжування зі збереженням меж → K-Means у Lab (фіксований seed) →
зв'язні області → граф сусідства → об'єднання малих і вузьких областей (карта значущості, контраст) →
прибирання виступів вужчих за мінімальну ширину → планарне розбиття (ребра згладжуються й спрощуються
з нерухомими вузлами) → перевірка топології → номери в полюсі недоступності (polylabel) →
специфікація → SVG/PDF/CSV/JSON.

Числа порогів у `paint_by_numbers/settings.py` --- стартові гіпотези з ТЗ (розділ 6.4), їх потрібно
уточнити фізичними тестами (розділ 21.5 ТЗ).

## Номери на виносках

Якщо номер не вміщається в ділянку, він ставиться у найближче вільне місце (до 12 мм), а до ділянки
веде тонка лінія із крапкою (SVG-група `leaders`, PDF, превʼю). Вибирається місце з найменшою
кількістю перетинів ліній контуру; виноска не торкається чужих цифр. Попередження `NUM_LEADER` (info)
показує кількість виносок. Ділянки, для яких не знайшлося місця навіть для виноски, автоматично
зливаються із сусідом (до 5 проходів); якщо щось усе ж лишилося, `NUM_NO_ROOM` --- критичне попередження
(виробничі файли блокуються). Тому в готовому макеті кожна ділянка має номер (перевіряє тест). Модуль: `paint_by_numbers/geometry/leaders.py`.


## Каталог фарб (CIEDE2000)

`--catalog examples/catalog_sample.json` замінює кольори палітри найближчими фарбами каталогу:
кожному кольору відповідає окрема фарба (оптимальне призначення за сумою ΔE2000, угорський алгоритм).
Превʼю, метрики й специфікація далі рахуються вже за кольорами реальних фарб; у `paint_list.csv`,
PDF і `project.json` зʼявляються код і назва фарби та ΔE2000. Попередження: `CAT_FAR` (немає близької
фарби, поріг `--catalog-max-de`, типово 10 --- гіпотеза) і `CAT_TOO_SMALL` (фарб менше, ніж кольорів).
Формат каталогу описано в `paint_by_numbers/palette/catalog.py`; `catalog_sample.json` --- умовний
зразок, а не реальний бренд: підставте свій каталог (hex або Lab кожної фарби).
CIEDE2000 перевірено на еталонних парах Sharma, Wu, Dalal (2005).


## Графічний інтерфейс

    pip install PySide6          # або: uv sync --extra gui
    python3 main_gui.py [фото.jpg]

Порядок роботи: відкрити фото -> задати розмір полотна й режим -> (за потреби) позначити зони
інструментами ▭ ◯ ⬠ (колесо миші --- масштаб; ✋ або середня кнопка миші --- посунути зображення, подвійний клік або клавіша 0 --- вмістити; для багатокутника: клік --- точка, подвійний клік,
Enter або права кнопка --- завершити; Esc --- скасувати) -> «Створити превʼю» -> перевірити вкладки
«Контури з номерами», «Кольори», «Порівняння», специфікацію й попередження -> «Зберегти пакет…».
Зміна будь-якого налаштування скасовує превʼю (пакет зберігається лише з актуального результату).
Зони можна завантажити з файлу й зберегти у файл у тому самому JSON-форматі, що й для командного рядка.
Якщо є критичні попередження, виробничі файли блокуються; інтерфейс запитає, чи створити їх попри це.
Налаштування (розмір полотна, режим, кольори, норма покриття N, коефіцієнт K, прапорець «підтверджено», шлях до каталогу фарб, розмір і положення вікна, останні папки) зберігаються між запусками: у реєстрі Windows (`HKCU\\Software\\paint-by-numbers`), на Linux --- `~/.config/paint-by-numbers/`. Зони й номер замовлення не зберігаються, бо стосуються конкретного фото. Меню «Файл → Скинути збережені налаштування» повертає типові значення; пошкоджені значення замінюються типовими автоматично.
Тести інтерфейсу працюють без екрана (`QT_QPA_PLATFORM=offscreen`).


## Порівняння варіантів і автовибір (розділ 14 ТЗ)

    python3 main.py фото.jpg --zones zones.json --compare [--compare-modes simple,balanced]
                             [--compare-colors 16,24,32] [--jobs 2]

За замовчуванням перебираються 3 режими x 3 кількості кольорів (типове значення режиму та ±8) = 9 варіантів;
кожен проходить повний конвеєр (у кількох процесах). Оцінка: `0.6 * точність + 0.4 * придатність до розфарбовування`,
де точність --- зважена за зонами ΔE76 і SSIM, а придатність штрафує ділянки без номера, виноски, вузькі й дрібні
ділянки щільність ділянок і витрати на фарбу (кількість ємностей, вага `--cost-weight`, типово 0.3; 0 вимикає). Варіанти з критичними помилками не обираються; за рівної оцінки перемагає менше
кольорів. **Усі ваги й пороги --- гіпотези** (константи в `paint_by_numbers/compare.py`), які треба
калібрувати на реальних замовленнях. Якщо відрив від другого місця < 0.02, у звіті є застереження.
У пакеті зʼявляються `quality/candidates.png` (аркуш мініатюр з показниками) і `quality/candidates.json`.
В інтерфейсі: кнопка «Підібрати найкращий варіант», вкладки «Варіанти» (зображення й таблиця); подвійний клік
по рядку таблиці застосовує будь-який варіант.

## Збирання .exe для Windows

На Windows 10/11 x64 встановіть Python 3.12+ (https://www.python.org/downloads/, позначте «Add python.exe to PATH»),
розпакуйте проєкт і двічі клацніть `packaging\build_windows.bat`. Скрипт створює віртуальне середовище, ставить
залежності (потрібен інтернет), проганяє тести, збирає програму PyInstaller і запускає самоперевірку.
Результат: `dist\PaintByNumbers\PaintByNumbers.exe` (графічний інтерфейс) і `pbn-cli.exe` (командний рядок,
`pbn-cli.exe --selftest`), а також архів `dist\PaintByNumbers.zip` для передачі. Python на комп'ютері замовника не потрібен.

* Шрифт DejaVu Sans (кирилиця в PDF) іде в комплекті; текст ліцензії --- `paint_by_numbers/assets/fonts/LICENSE-DejaVu.txt`.
  Його треба зберігати в поставці.
* Папка зібраної програми важить ~0,5 ГБ (Qt, OpenCV, SciPy); архів менший. Це нормально для PyInstaller.
* Першу збірку було перевірено на Linux тією самою специфікацією (`packaging/build.sh`): програма стартує,
  `--selftest` проходить, зокрема PDF із кирилицею та порівняння варіантів у дочірніх процесах.
  На Windows збірку ще не запускали: перший запуск `build_windows.bat` --- справжня перевірка.
* Антивіруси іноді реагують на непідписані .exe з PyInstaller; для поширення потрібен цифровий підпис коду.
